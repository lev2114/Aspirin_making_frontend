ЛАБОРАТОРНАЯ РАБОТА №5 — ФРОНТЕНД «ЭТАПЫ СИНТЕЗА АСПИРИНА»

Что сделано

Создано SPA на React и TypeScript с Vite и React-Bootstrap на основе
подготовленного проекта. За основу интерфейса взяты HTML-шаблоны ленты
и плитки из aspirin_back/templates и стили aspirin_back/resources/styles.
Шаблоны Go перенесены в React-компоненты. Исходный backend не изменялся.
Из backend скопированы default.png, default.mp4, heart.png и next.png:
теперь они находятся в public/media и доступны без запущенного сервера.

Сохранены основные элементы исходного оформления: мобильная колонка
375 px, тёмный фон вокруг приложения, синяя нижняя панель, видеолента
с боковыми показателями и двухколоночная плитка. Для узких экранов
ширина приложения уменьшается. Добавлены адаптации к React-Bootstrap,
стили фокуса клавиатуры и русскоязычные заголовки страницы.

Две страницы

1. Лента: /aspirin-synthesis-stage
Показывает видео одного этапа, название, описание, длительность,
выход продукта и количество лайков. Кнопки «Развернуть» и «Свернуть»
управляют описанием.
Стрелка открывает следующий этап, после последнего — первый.
ID выбранной записи хранится в query-параметре
aspirin_synthesis_stage_id, поэтому ссылку можно открыть напрямую.

2. Плитка: /aspirin-synthesis-stages
Карточки содержат изображение, название, длительность и лайки.
Нажатие на изображение или название открывает выбранный этап в ленте.
Ползунок задаёт максимальную длительность от 0 до 30 минут.
Кнопка «Применить фильтр» применяет выбранное ограничение,
«Сбросить фильтр» возвращает всю коллекцию. Есть счётчик результатов
и сообщение для пустого списка. Применённый фильтр сохраняется при
переходах между страницами до перезагрузки приложения.

Навигация

Внизу закреплена панель из четырёх пунктов: «Лента», «Добавление»,
«Плитка», «Вход». Доступны только лента и плитка. Добавление и вход
отключены. Изменение записей, удаление и отправка лайков не реализованы,
поскольку эта лабораторная посвящена просмотру для гостя.
Переходы выполняются через React Router без перезагрузки документа.
Корневой маршрут / перенаправляет в ленту. Для неизвестного маршрута
есть сообщение со ссылкой к плитке.

Mock-данные и типы

src/types/stage.ts описывает Stage с полями JSON существующего Go API.
src/data/stages.ts содержит шесть демонстрационных этапов: подготовка
реагентов, ацетилирование, кристаллизация, фильтрация, сушка и контроль
качества. Значения учебные, а не результаты реального эксперимента.
По умолчанию все страницы получают данные только из этой коллекции:
HTTP-запросы к backend не выполняются. Загружаются лишь файлы приложения
и локальные медиа. В коллекции предусмотрены заполненные, пустые и null
поля изображения и видео для демонстрации подстановки файлов по умолчанию.

Изображение и видео по умолчанию

src/components/StageMedia.tsx содержит StageImage и StageVideo.
Если поле отсутствует по смыслу (null, пустая строка или пробелы),
подставляется /media/default.png или /media/default.mp4.
При ошибке загрузки указанного медиа также используется локальный файл.
При ошибке самого стандартного видео показывается «Видео недоступно».
Смена ID этапа сбрасывает состояние ошибок через React key.
Видео имеет стандартные элементы управления браузера, muted, loop,
playsInline и preload="metadata".

Компоненты, props и состояние

App получает коллекцию из useStages и хранит применённый фильтр.
GridPage получает stages, maxDuration и onFilter через props.
Он фильтрует коллекцию и передаёт каждую запись в StageCard через stage.
DurationFilter получает value и onApply, хранит редактируемое значение
ползунка отдельно и вызывает onApply при отправке формы.
Обработчик формы использует preventDefault, поэтому документ не обновляется.
BottomNav отвечает за нижнюю панель. FeedPage и GridPage
отвечают за содержимое соответствующих маршрутов.
Используются Navbar, Card, Form, Form.Range, Button, Alert и Spinner
из React-Bootstrap. Redux и пользовательский Context не используются.

Используемые хуки

useState: применённый фильтр в App, значение ползунка в DurationFilter,
раскрытие описания в FeedPage, состояние ошибок медиа, а также коллекция,
загрузка, ошибка и номер повторной попытки в useStages.

useEffect в App: обновление document.title и прокрутка вверх при смене
маршрута. useEffect в useStages: загрузка данных при включённом API-режиме
и повторной попытке. Cleanup отменяет незавершённый запрос через
AbortController. В mock-режиме запрос не выполняется.

useSearchParams в FeedPage: чтение и изменение ID этапа в URL.
useLocation в App: определение текущей страницы.
useStages: пользовательский хук, объединяющий загрузку и её состояние.

Необязательное подключение к backend

.env.example содержит VITE_USE_API=false. Для API-режима нужно скопировать
его в .env.local, установить VITE_USE_API=true и перезапустить Vite.
Backend должен работать на http://localhost:8080.
Выполняется GET /api/aspirin-stages, из ответа читается массив data.
Все страницы используют эту коллекцию; фильтрация остаётся клиентской.
В vite.config.ts настроен dev proxy с /api на http://localhost:8080
без удаления префикса /api. Поэтому в разработке запросы идут через
тот же origin. Backend менять не требуется. При ошибке показываются
сообщение и кнопка «Повторить»; скрытого перехода на mock нет.
Медиа, возвращённые API, должны быть доступны по своим URL.
Для размещения production-сборки нужен отдельный reverse proxy для /api
и возврат index.html для маршрутов SPA: Vite dev proxy в production
не работает.

Прочие изменения

В main.tsx подключены Bootstrap CSS и BrowserRouter.
В index.html установлен русский язык и описание приложения.
Добавлена локальная SVG-иконка вкладки.

Исходные неиспользуемые ресурсы шаблона Vite могут оставаться в проекте;
они не участвуют в интерфейсе приложения.

Запуск после распаковки

1. Установить Node.js 20.19+ или 22.12+; подходит Node.js 24.
2. Открыть терминал в папке aspirin_front из архива.
3. Выполнить npm ci.
4. Выполнить npm run dev.
5. Открыть http://localhost:3000.

При использовании nvm можно сначала выполнить nvm use 24.
Для стандартной демонстрации backend и .env.local не нужны.
Команда npm run build собирает приложение в dist.
Команда npm run preview позволяет открыть собранное приложение локально.

Проверка выполненной работы

Проверка TypeScript, production-сборка Vite и ESLint завершились успешно.
Первый запуск сборки через системный Node.js 18 выявил несовместимость
с установленным Vite; сборка успешно выполнена с установленным Node.js 24.
Тесты не писались и не запускались. Скриншоты, отчёт по лабораторной
и расчёт аппаратных требований не создавались по исходному запросу.
Интерактивная проверка в браузере не выполнялась.

Содержимое архива

package.json, package-lock.json, настройки TypeScript, Vite и ESLint,
